# Sales Quota Progress with Running Totals

## Business Problem

A sales manager wants to track each employee's progress toward their sales quota throughout the year.

A single percentage-of-quota metric only shows the employee's current position and does not reveal how their performance developed over time. To provide more visibility, the analysis should calculate a cumulative sales total after each sale and show how much of the employee's quota has been reached at that point.

## Relevant Data

The analysis uses two tables:

### `Sales`

Contains individual sales transactions, including:

* `SalesEmployeeID` — identifies the employee who made the sale
* `SaleDate` — date of the sale
* `SaleAmount` — revenue generated by the sale

### `Employees`

Contains employee information, including:

* `EmployeeID` — unique employee identifier
* `Quota` — sales target assigned to the employee

## Objective

For each sales employee and sale date, return:

* `salesemployeeid` — employee identifier
* `saledate` — date of the sale
* `saleamount` — amount of the individual sale
* `quota` — employee's assigned sales quota
* `running_total` — cumulative sales revenue up to that point
* `percent_quota` — proportion of the employee's quota reached

## Approach

The solution joins sales transactions with employee quota information.

A window function calculates cumulative sales for each employee using `SUM() OVER()`. The data is partitioned by employee so that each salesperson has an independent running total and ordered by sale date so that revenue accumulates over time.

The running total is then divided by the employee's quota to calculate progress toward the target.

## SQL Concepts Used

* Common Table Expressions (CTEs)
* Window functions
* `SUM() OVER()`
* `PARTITION BY`
* `ORDER BY`
* `JOIN`
* `CAST()`
* Running totals
